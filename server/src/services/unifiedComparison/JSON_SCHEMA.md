# UnifiedComparisonResult JSON Schema Documentation

## Overview

The `UnifiedComparisonResult` is the structured output format generated by the Unified Comparison Engine. It represents a comprehensive comparison of multiple insurance quotes in a single JSON object.

## Schema Structure

```json
{
  "metadata": { ... },
  "client": { ... },
  "insurers": [ ... ],
  "coverageMatrix": [ ... ],
  "financials": { ... },
  "analysis": { ... }
}
```

## Top-Level Fields

### Required Fields

All top-level fields are required:
- `metadata`: Processing metadata
- `client`: Client information
- `insurers`: Array of insurer details
- `coverageMatrix`: Coverage comparison matrix
- `financials`: Financial breakdown
- `analysis`: Automated analysis and recommendations

---

## metadata

Processing metadata about the comparison generation.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `generatedAt` | string | Yes | ISO 8601 timestamp of generation |
| `model` | string | Yes | Gemini model used (e.g., "gemini-3.5-flash") |
| `thinkingLevel` | string | Yes | Thinking configuration ("LOW", "MEDIUM", "HIGH") |
| `pdfCount` | number | Yes | Number of PDFs processed |
| `totalPages` | number | No | Total pages across all PDFs |
| `confidence` | number | Yes | Overall confidence score (0.0 to 1.0) |
| `needsHumanReview` | boolean | Yes | Whether manual review is recommended |
| `processingTimeMs` | number | No | Processing time in milliseconds |

### Confidence Score Interpretation

- **0.9 - 1.0**: Excellent - Results are highly reliable
- **0.7 - 0.9**: Good - Results are reliable with minor caveats
- **0.5 - 0.7**: Fair - Results may have some inaccuracies, review recommended
- **0.0 - 0.5**: Poor - Results should be manually verified

## client

Information about the insured entity.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Client/company name |
| `activity` | string | Yes | Economic activity description |
| `ciiu` | string | No | CIIU code (Colombian industry classification) |
| `address` | string | Yes | Risk address |
| `city` | string | Yes | City of risk |
| `totalInsuredValue` | number | Yes | Total sum insured |

---

## insurers

Array of insurer details, one per quote.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Insurance company name |
| `quoteDate` | string | Yes | Quote date (ISO 8601) |
| `validity` | string | Yes | Quote validity period |
| `product` | string | Yes | Product name (e.g., "PYME", "Empresarial") |
| `logo` | string | No | URL or identifier for insurer logo |

---

## coverageMatrix

The core comparison structure. Array of coverage categories, each containing rows of data.

### Coverage Section

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `category` | string | Yes | Coverage category name (e.g., "INCENDIO", "RCE") |
| `isExclusive` | boolean | No | Whether this category is exclusive to one insurer |
| `rows` | array | Yes | Array of data rows |

### Coverage Row

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | string | Yes | Row type: "value", "deductible", "includes", "exclusions", "notes" |
| `label` | string | Yes | Human-readable label |
| `cells` | array | Yes | Array of cell values, one per insurer |

### Cell

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `value` | string | Yes | Cell value (can be null for "N.C.") |
| `rawText` | string | No | Raw extracted text from PDF |
| `confidence` | number | No | Confidence score for this cell (0.0 to 1.0) |
| `pageNumber` | number | No | Source page in PDF |
| `isAmbiguous` | boolean | No | Whether value requires manual verification |
| `notes` | string | No | Additional notes or warnings |

### Row Types

- **value**: Coverage value/sum insured
- **deductible**: Deductible amount or percentage
- **includes**: What's included in the coverage
- **exclusions**: What's excluded from the coverage
- **notes**: Additional notes or conditions

## financials

Financial breakdown for each insurer.

### premiums

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `insurer` | string | Yes | Insurer name |
| `netPremium` | number | No | Net premium amount |
| `fees` | number | No | Administrative fees |
| `taxes` | number | No | Taxes (typically 19% IVA in Colombia) |
| `total` | number | No | Total payable amount |
| `percentageOfValue` | number | No | Premium as percentage of insured value |

### metadata

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `insurer` | string | Yes | Insurer name |
| `commission` | string | No | Commission percentage |
| `backing` | string | No | Reinsurance backing |
| `modality` | string | No | Insurance modality |
| `asistencia` | string | No | Assistance services included |

---

## analysis

Automated analysis and recommendations.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `bestValue` | string | No | Insurer with best value proposition |
| `warnings` | array | Yes | Array of warning strings |
| `missingCoverages` | array | Yes | Missing coverages by insurer |
| `significantDifferences` | array | Yes | Significant differences between quotes |

### missingCoverages Item

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `insurer` | string | Yes | Insurer name |
| `coverage` | string | Yes | Missing coverage name |

### significantDifferences Item

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `coverage` | string | Yes | Coverage category |
| `difference` | string | Yes | Description of difference |
| `severity` | string | Yes | "high", "medium", or "low" |

## Validation

The schema is enforced using Google's GenAI JSON Schema format. The engine validates:

1. **Required fields**: All required fields must be present
2. **Types**: Values must match declared types
3. **Enums**: String values must match allowed values
4. **Nullable**: Some fields can be null (marked with `nullable: true`)

### Validation Errors

If validation fails, the engine will:
1. Log the validation error with correlation ID
2. Attempt to retry with a correction prompt (up to 2 retries)
3. Fall back to legacy engine if retries fail
